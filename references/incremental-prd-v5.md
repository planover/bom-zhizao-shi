## 2. 产品目标

> **V5 目标：在 V4 多行业框架之上，把专属视图覆盖到纺织、家具两个高频行业，并将电子、化工的专属字段做工程级/合规级深化（制造商、容差、额定功率/电压、替代料、封装温度；纯度、物态、闪点、存储条件、危险等级）；同时叠加跨行业的成本视图与行业模板预设，使工具在"行业更深、字段更全、录入更轻"三个维度上保持物料区 8 列不变与 100% 向后兼容。**

三个正交子目标：
1. **行业视图补齐**：纺织 → 面料辅料清单视图、家具 → 家具物料清单视图（与食品/电子/化工并列，同构派生）。
2. **专属字段深化**：电子/化工在现有 4/3 字段基础上扩充工程与合规字段，仍遵循"仅存 JSON、仅专属视图展示"模式。
3. **跨行业能力附加**：成本视图（单价/币种/总价）与行业模板预设（一键载入字段集/物料类型/标准/工序建议），提升核算效率与录入体验；机械/包装维持通用兜底（P2 仅评估不实现）。

## 8. 成本视图设计

### 8.1 JSON 结构（增量）

```json
{
  "materials": [
    {
      "name": "贴片电阻", "unit": "个", "usage": 100, "yield_rate": 100,
      "erp_code": "R-001", "material_type": "电阻", "process": "S01",
      "unit_price": 0.02,          // 新增（选填）
      "currency": "人民币(CNY)",    // 新增（选填，默认人民币(CNY)）
      "total_price": ""            // 派生展示，默认空；生成时按 usage×unit_price 计算
    }
  ]
}
```

- `unit_price` / `currency` 入库（参与逆向回写）；`total_price` 推荐**派生展示**（用量×单价），不强制入库（详见 Q4）。
- 物料区 8 列不变；成本字段不进物料区。

### 8.2 Excel 呈现（四、成本明细）

| 列 | A | B | C | D | E | F | G | H |
|----|---|---|---|---|---|---|---|---|
| 表头 | 序号 | 物料名称 | 物料类型 | 用量 | 单位 | 单价 | 币种 | 总价 |
| 取值 | 1..N | name | material_type | usage | unit | unit_price | currency | usage×unit_price |
| 合计 | 成本合计 | — | — | — | — | — | — | Σ 总价 |

- **编号规则**：当已存在行业专属视图（占「三、」）时，成本视图为「**四、成本明细**」；当行业为通用/机械/包装/纺织/家具等**无行业视图**场景时，成本视图顶替为「**三、成本明细**」。逆向以关键字 `成本明细` 识别（兼容「三、/四、」前缀）。
- **触发**：任一物料含非空 `unit_price` 即生成；全空则不生成（不影响现有 BOM）。
- **数字格式**：单价/总价按数值格式（币种非数值列）；总价合计行纯展示、逆向跳过。

## 11. 向后兼容与逆向（增量摘要）

| 场景 | V5 行为 | 与 V4 对比 |
|------|---------|-----------|
| 旧 JSON（无纺织/家具/成本/扩列字段） | 推断 industry 后，纺织/家具视图不触发、元件清单/配方表保持 8 列、成本块不生成 | ✅ 完全一致 |
| 旧 Excel（无新区块） | 无「三、面料辅料清单/家具物料清单/成本明细」marker → 不回收新字段，全部默认空 | ✅ 完全兼容 |
| 新 JSON industry=纺织/家具 | 生成对应专属视图；其他行业照常 | V4 无此能力（新功能） |
| 元件清单/配方表扩列 | marker 仍为「三、元件清单/三、配方表」，逆向按扩展表头回收全部字段 | V4 仅回收 4/3 字段，超集兼容 |
| 成本块 | marker 关键字 `成本明细`（兼容三、/四、前缀），回收 unit_price/currency | 新功能 |

- 新增专属字段在逆向输出时一律补全默认空串（未回收到的）。
- 不引入新第三方依赖；列宽超出 H 列（I–N / I–M）由架构师按内容设定（见 Q2）。

## 12. 待确认问题

| # | 问题 | 推荐默认 | 理由 |
|---|------|----------|------|
| Q1 | 用户原话将「行业模板预设」「成本视图」标为"P2 预留"，本 PRD 按主理人拆解提升为 **P1**。是否确认提升？ | **按主理人拆解提升为 P1** | 成本与模板预设对多行业复用价值高；若维持 P2 则挪入 P2 组 |
| Q2 | 电子/化工专属字段扩充的**呈现方式**：是将 6/5 新字段直接并入「三、元件清单/配方表」使其扩列至 14/13 列（单区块、逆向简单），还是保留 8 列核心视图 + 新增独立「四、元件规格参数/配方规格」区块？ | **扩列并入（单区块）** | 逆向仅需识别一个 marker，闭环最简单；代价是视图更宽，列宽需重新设定 |
| Q3 | 成本视图**编号规则**：有行业视图时「四、成本明细」、无行业视图时「三、成本明细」，是否认可？ | **认可双编号（关键字 `成本明细` 识别）** | 保证首个派生区块恒为「三、」、成本恒在其后，结构清晰 |
| Q4 | `total_price` 是否入库（JSON）？ | **派生展示（用量×单价），不入库** | 可由用量与单价稳定重算，减少冗余与回写歧义；如业务需改单价后保留历史总价则改为入库 |
| Q5 | 机械/包装本期是否仅**评估不实现**（P2 草案），还是连评估都延后？ | **P2 仅评估出草案** | 给出结论供后续版本拍板，避免范围膨胀 |
| Q6 | 纺织/家具 `material_type` 建议值集合与过滤排除规则（默认排除"其他"类）是否合适？ | **排除"其他"类** | 与 V4 电子/化工过滤同构，避免辅料/包装噪音进视图 |
| Q7 | 行业模板预设（P1）是否携带**建议工序模板**（preset_processes 一键载入）？ | **携带，可选一键载入** | 进一步降低录入负担；若担心干扰现有工序流程，可改为仅展示不自动载入 |
