## 2. 机械行业视图字段草案（建议，未采纳）

> 形态参考：与电子「三、元件清单」、化工「三、配方表」同构的「三、机械物料清单」。
> 字段建议如下（均为物料级专属字段，选填，默认空串）：

| 字段（JSON key） | 中文名 | 类型 | 说明 / 示例 |
|------------------|--------|------|-------------|
| `drawing_no` | 图号 | string | 零部件图纸编号，如 `DW-2026-011` |
| `material` | 材质 | string | 如 `Q235` / `45#钢` / `铝合金6061` |
| `heat_treatment` | 热处理 | string | 如 `淬火+回火` / `退火` / `无` |
| `surface_treatment` | 表面处理 | string | 如 `镀锌` / `喷塑` / `阳极氧化` |
| `weight` | 重量 | number | 单件总重量（kg） |
| `unit_weight` | 单重 | number | 单位重量（kg/件），与 weight 可并存或二选一 |

**若未来实现**，列宽建议（A–H 基础上向右扩列，仿电子 14 列范式）：
`[6,18,18,16,14,14,16,14]`（序号/物料名称/图号/材质/热处理/表面处理/重量/单重），
具体以立项时实际字段数为准。

## 4. 评估结论（建议：本期不实现）

| 维度 | 结论 | 说明 |
|------|------|------|
| 是否实现 | **否（维持通用兜底）** | industry ∈ {机械, 包装} 不生成专属视图 |
| 样本量 | 低 | 当前示例与真实需求中机械 / 包装样本极少，不足以支撑字段标准化 |
| 标准化成本 | 高 | 专属字段命名 / 单位 / 回收规则需重新设计、测试、文档化 |
| 兼容性风险 | 中 | 扩列会引入新列、增加逆向回收分支；本期追求最低回归风险 |
| 通用兜底能力 | 充足 | 基础物料区 8 列（A–H）已能承载图号 / 材质 / 尺寸等基础信息；专属字段可由用户在「物料名称」中临时表述 |

**理由**：V4 已确立「通用兜底」策略并被验证稳定；机械 / 包装无高频刚性需求，
为避免无谓的复杂度与回归风险，本期沿用通用视图。

**未来实现路径（若立项）**：
1. 复用现有 `derive_*` 同构范式（`derive_mechanical` / `derive_packaging`），过滤集参考 `COMPONENT_EXCLUDE` 思路；
2. 在 `bom_constants.py` 的 `INDUSTRY_TEMPLATES` 中补 `机械` / `包装` 的 `material_types` / `special_fields` / `preset_processes`；
3. 在 `generate_bom.py` 的 `build_workbook` 增加 `elif industry == "机械" / "包装"` 分支与列宽；
4. 在 `import_bom.py` 增加对应 marker 识别与 `field_col_map` 回收，并在 `_infer_industry_from_blocks` 注册 marker；
5. **无需新架构、无需新依赖**，完全沿用 V5 已建立的增量范式。

## 5. 本期（V5）机械 / 包装相关实际产出

- `INDUSTRY_TEMPLATES` 字典中已占位 `机械` / `包装` 空模板（material_types / special_fields / preset_processes 均为空），
  保证 `INDUSTRY_TEMPLATES[industry]` 查表永不 KeyError，行为与通用一致。
- `INDUSTRY_VIEW_SET`（成本视图双编号判定集合）**不含**机械 / 包装，因此即便机械 / 包装物料带 `unit_price`，
  成本视图仍按「三、成本明细」渲染（与通用同口径）。
- 逆向 `import_bom.py` 对机械 / 包装 Excel 按 `_infer_industry_from_blocks` 回退为 `CATEGORY_TO_INDUSTRY` 推断，
  与 V4 完全一致，无新增分支。

> 结论：本期机械 / 包装**零代码实现、零回归风险**，仅以空模板占位 + 本草案文档沉淀评估结论。
