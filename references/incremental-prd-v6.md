## 2. 产品目标

> **V6 目标：把 V5 评估草案中"暂不做"的机械/包装专属视图正式落地，补全 8 大行业专属视图的最后两块拼图，使 BOM 智造师在行业覆盖上形成完整闭环（食品/电子/化工/纺织/家具/机械/包装全覆盖 + 通用兜底 + 跨行业成本视图）。**

V6 是 V5 评估草案（P2-1/P2-2）的**正式立项实现**：机械工程师出图 BOM、包装工程师出包材 BOM，均可在「三、」派生专属视图中展示图号/材质/热处理/表面处理/重量、以及材质/克重/尺寸/印刷工艺/环保标识，无需再把专业字段塞进"物料名称"。同时机械/包装纳入 `INDUSTRY_TEMPLATES` 与成本视图双编号集合，使模板引导与成本核算与既有 5 行业完全同构。全部新增字段选填默认空、仅存 JSON、仅专属视图展示，物料区 8 列不变，100% 向后兼容。

三个正交子目标：
1. **机械专属视图落地**：`industry=="机械"` → 工序区后追加「三、机械物料清单」派生区块（8 列 A–H），承载图号/材质/热处理/表面处理/重量/单重 6 个专属字段。
2. **包装专属视图落地**：`industry=="包装"` → 工序区后追加「三、包装物料清单」派生区块（8 列 A–H），承载材质/克重/尺寸/印刷工艺/环保标识 5 个专属字段。
3. **同构收口**：机械/包装纳入 `INDUSTRY_TEMPLATES`（填实 material_types/standard/special_fields/preset_processes）与 `INDUSTRY_VIEW_SET`（成本视图双编号），与纺织/家具同口径，零新架构、零新依赖。

## 5. 字段定义（新增行业专属字段）

> 全部选填、默认空串 `""`；仅存 JSON、仅在对应专属视图展示；不影响 V1–V8/含量和 等任何阻断/软校验逻辑（沿用 V5 同构排除提示）。**机械的 `material` 与包装的 `material` 同名 JSON key（行业互斥，无冲突）；机械的 `surface_treatment` 与家具同名 key（行业互斥，无冲突）。**

### 5.1 机械新字段（展示位置：三、机械物料清单 A–H）

| JSON key | 中文表头 | 类型 | 必填 | 默认值 | 展示位置 |
|----------|----------|------|------|--------|----------|
| `drawing_no` | 图号 | string | 否 | `""` | 机械物料清单 C 列 |
| `material` | 材质 | string | 否 | `""` | 机械物料清单 D 列 |
| `heat_treatment` | 热处理 | string | 否 | `""` | 机械物料清单 E 列 |
| `surface_treatment` | 表面处理 | string | 否 | `""` | 机械物料清单 F 列 |
| `weight` | 重量(kg) | number | 否 | `""` | 机械物料清单 G 列 |
| `unit_weight` | 单重(kg/件) | number | 否 | `""` | 机械物料清单 H 列 |

> 轻量微调说明：草案原 `weight` 释义为"单件总重量(kg)"、`unit_weight` 为"单位重量(kg/件)"，二者语义接近。本 PRD **暂保留两个字段**（与草案一致、零歧义），是否合并为单「重量」字段交由待确认问题 Q1 拍板。

### 5.2 包装新字段（展示位置：三、包装物料清单 A–H）

| JSON key | 中文表头 | 类型 | 必填 | 默认值 | 展示位置 |
|----------|----------|------|------|--------|----------|
| `material` | 材质 | string | 否 | `""` | 包装物料清单 D 列 |
| `basis_weight` | 克重(g/m²) | number | 否 | `""` | 包装物料清单 E 列 |
| `size` | 尺寸 | string | 否 | `""` | 包装物料清单 F 列 |
| `print_process` | 印刷工艺 | string | 否 | `""` | 包装物料清单 G 列 |
| `eco_label` | 环保标识 | string | 否 | `""` | 包装物料清单 H 列 |

> 轻量微调说明：草案 `basis_weight` 类型列为 number（克重为数值，与纺织 `fabric_weight` 同构），本 PRD 维持 number；`size`/`print_process`/`eco_label` 为字符串（尺寸/工艺/标识无强格式约束）。

## 6. 视图列定义

### 6.1 机械 — 三、机械物料清单（8 列 A–H）

| 列 | A | B | C | D | E | F | G | H |
|----|---|---|---|---|---|---|---|---|
| 表头 | 序号 | 物料名称 | 图号 | 材质 | 热处理 | 表面处理 | 重量(kg) | 单重(kg/件) |
| 取值 | 1..N | name | drawing_no | material | heat_treatment | surface_treatment | weight | unit_weight |
| 对齐 | center | left | center | left | center | center | center | center |

- **触发**：`industry == "机械"`
- **过滤排除**：`material_type ∈ MECHANICAL_EXCLUDE`（默认 `{"其他"}`）
- **排序**：物料类型升序 → 物料名称升序（与 V5 纺织/家具同构；空 material_type 视为"其他"排末尾）
- **物料类型建议值** `MECHANICAL_TYPES = ["零部件","标准件","型材","铸件","焊接件","其他"]`

- **说明**：因 6 个专属字段 + 序号 + 物料名称已占满 8 列，**本视图不单列「物料类型」展示列**（物料类型仍用于过滤/排序，从物料区/JSON 取）。若需展示该列需扩至 9 列（见待确认 Q2）。

> 列宽：复用 8 列基线 `[6,18,10,10,13,16,13,12]`；建议 C(图号)=16、G/H(重量/单重)各=12–14。

> 列宽：复用 8 列基线 `[6,18,10,10,13,16,13,12]`；建议 E(克重)=12、F(尺寸)=18。

## 7. 成本视图双编号设计（硬约束，已拍板）

- **判定集合扩展**：`INDUSTRY_VIEW_SET` 由 V5 的 `{食品,电子,化工,纺织,家具}` **扩展为** `{食品,电子,化工,纺织,家具,机械,包装}`。
- **编号规则**：当 `industry ∈ INDUSTRY_VIEW_SET`（即已存在「三、」行业派生视图）→ 成本视图为「**四、成本明细**」；当 `industry ∈ {通用}`（无行业视图）→ 成本视图为「**三、成本明细**」。
  - 机械/包装带成本 → 「**四、成本明细**」（因机械/包装已有「三、机械/包装物料清单」）。
  - 机械/包装不带成本 → 仅「三、机械/包装物料清单」，无成本块。
  - 通用 → 仅「三、成本明细」（如有成本）。
- **触发**：任一物料含非空 `unit_price` 即生成；全空不生成（不影响现有 BOM）。
- **total_price 派生不入库**：沿用 V5，`total_price = round(usage × unit_price, 2)` 实时计算，正向输入 JSON 与逆向输出 JSON **均不含** `total_price`。
- **逆向识别**：以关键字 `成本明细` 匹配首列（兼容「三、/四、」前缀），回收 `unit_price`/`currency`，与 V5 完全一致。
- **成本视图 8 列 A–H 表头**（沿用 V5，不变）：`序号|物料名称|物料类型|用量|单位|单价|币种|总价`。

> 向后兼容说明：V5 中 `industry==机械/包装` 且带成本时生成的是「三、成本明细」（当时机械/包装无行业视图）。V6 起该场景改为「四、成本明细」——这是主理人拍板的**预期行为变更**（因机械/包装新增了「三、」行业视图），数据内容完全一致；逆向以关键字识别，旧 Excel 仍可正确回收，无需迁移。

    "special_fields": ["drawing_no","material","heat_treatment",
                       "surface_treatment","weight","unit_weight"],

        {"step_no":"S01","name":"下料","desc":"切割/锯切下料","output":"坯料"},
        {"step_no":"S02","name":"机加工","desc":"车铣钻加工","output":"加工件"},
        {"step_no":"S03","name":"热处理","desc":"淬火/回火等","output":"热处理件"},
        {"step_no":"S04","name":"表面处理","desc":"镀锌/喷塑/阳极氧化","output":"表面处理件"},
        {"step_no":"S05","name":"装配","desc":"零部件组装","output":"成品"},
    ],
}

### 8.2 行为（与 V5 同构）

- 阶段零选 `industry` 后，阶段一物料模板按 `special_fields` 动态追加专属字段行；`material_type` 下拉用 `material_types`；`standard` 自动预填（可改）。
- 可选「一键载入工序模板」：将 `preset_processes` 写入阶段二（用户确认/可编辑）。
- **仅交互引导，不向 JSON 新增任何结构字段**；向后兼容旧交互流程（通用/机械/包装以前为空模板，现填实不影响旧 JSON）。

## 10. 向后兼容与逆向（增量摘要）

| 场景 | V6 行为 | 与 V5 对比 |
|------|---------|-----------|
| 旧 JSON（无机械/包装字段） | 推断 industry 后，机械/包装视图不触发、物料区 8 列不变；带成本时按新双编号生成「四、成本明细」 | ✅ JSON 零变化；仅带成本机械/包装 Excel 的成本块编号由「三、」变「四、」（预期行为变更，数据内容一致） |
| 旧 Excel（无新区块） | 无「三、机械/包装物料清单」marker → 不回收新字段，全部默认空 | ✅ 完全兼容 |
| 新 JSON industry=机械/包装 | 生成对应专属视图；其他行业照常 | V5 无此能力（新功能） |
| 逆向 机械/包装 Excel | `_infer_industry_from_blocks` 增「三、机械物料清单」→机械、「三、包装物料清单」→包装；各自 marker 回收 6/5 字段 | V5 无此分支；超集兼容 |
| 成本块（机械/包装带成本） | marker 关键字 `成本明细`（兼容 三/四 前缀），回收 unit_price/currency | 与 V5 完全一致 |
| 行业模板预设 | 机械/包装由空模板填实；旧交互不受影响（通用仍空模板） | V5 空模板占位 → 现填实，行为更友好 |

- 新增专属字段在逆向输出时一律补全默认空串（未回收到的）；`_SPECIAL_FIELDS` 唯一 JSON 键由 V5 的 **28 个**增至 **37 个**（净增 9：机械 6 + 包装 5，扣机械/包装同 key 的 `material` 1 个、以及 V5 家具已有的 `surface_treatment` 1 个；实现与测试以 **37** 为准，详见设计文档 §8.3 完整键表与 `test_v5_t26` 断言 28→37 的修正建议）。
- 不引入新第三方依赖；列宽超出 H 列（本版机械/包装均为 8 列，无扩列）沿用基线，无需重设。

## 11. 待确认问题

| # | 问题 | 推荐默认 | 理由 |
|---|------|----------|------|
| Q1 | 机械 `weight`（单件总重量 kg）与 `unit_weight`（单位重量 kg/件）是否都保留，还是合并为单一「重量」字段？ | **暂保留两个字段**（与 V5 草案一致） | 草案已分别定义，零歧义；若出现大量仅填其一的情况，后续可合并；合并需改 JSON 结构与逆向回收，V6 不值得为此增加回归面 |
| Q2 | 机械视图是否需要在 8 列内保留「物料类型」展示列？（当前建议方案为舍弃该列，因 6 专属字段已占满 8 列，物料类型仅用于过滤/排序）若需展示，是否接受扩至 9 列（A–I）？ | **舍弃展示列、维持 8 列 A–H**（与草案建议列序一致） | 维持 A–H 8 列与纺织/家具视图同构最简洁；扩 9 列会打破本视图列数一致，且物料类型已在物料区存在，视图内价值有限 |
| Q3 | 机械/包装 `material_types` 枚举（MECHANICAL_TYPES=[零部件,标准件,型材,铸件,焊接件,其他]；PACKAGING_TYPES=[纸箱,缓冲,标签,胶带,薄膜,其他]）是否合理，是否需要增删（如机械加"外购件/外协件"、包装加"托盘/缠绕膜"）？ | **采用上方建议值** | 覆盖主流类别且含"其他"兜底；作为交互引导非强制枚举，后续可随样本补充 |
| Q4 | 机械/包装 `standard` 默认预填值（机械 GB/T 1804-2000 一般公差；包装 GB/T 6543-2008 瓦楞纸箱）是否合适？ | **采用上方默认，可改** | GB/T 6543 为包装常识标准；GB/T 1804 为机械通用公差，可作为合理默认，用户按实际产品改填具体图号/产品标准 |
| Q5 | 包装 `eco_label` 是否下沉为受限枚举（FSC/可回收/可降解/食品级…）还是保持自由文本？ | **保持自由文本（V6）** | 环保标识表述多样（含组合），受限枚举易漏；P2-2 已列为未来评估，V6 不新增校验 |
